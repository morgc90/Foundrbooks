push, and let Vercel redeploy. Everything below has been built and verified with

## What changed and why

### 1. The site now ships real HTML (this was the core problem)

Create React App served a single empty `index.html`. Googlebot received
`<div id="root"></div>` and a noscript line — no headings, no copy, nothing to
rank. It was indexed, but with roughly 40 words of meta tags as its entire
content.

`scripts/prerender.mjs` runs automatically after `react-scripts build`. It
renders each route to static HTML with esbuild + `renderToString`, injects that
route's own head tags, and writes the result.

Measured output:

| Route | Words in HTML before | After |
|---|---|---|
| `/` | 0 | 764 |
| `/saas-accounting` | — | 1,577 |

### 2. Real routing, and per-route SEO metadata

There was no router — one component, anchor links only. Now:

- `/` — homepage
- `/saas-accounting` — the new specialty page
- `/success` — the Stripe return URL, which previously had no route at all
- `/404` — real not-found page

`src/seo.js` is the single source of truth for every route's title,
description, canonical, Open Graph tags and JSON-LD. Both the prerenderer and
the client-side `<Seo>` component read from it, so they can't drift apart.

### 3. Unknown URLs now 404 properly

`vercel.json` previously rewrote **every** path to `index.html`, so junk URLs
returned 200 with the homepage. That's what produced the "Alternate page with
proper canonical tag ×10" entries in Search Console. The catch-all is gone;
`build/404.html` is served with a real 404 status.

### 4. Missing assets generated

`favicon.ico`, `logo192.png` and `og-image.png` were referenced in
`index.html` but absent from the repo — hence the 404s in Search Console and
broken link previews on LinkedIn/Twitter/WhatsApp. Generated by
`scripts/make-assets.py` (re-run it any time to regenerate).

### 5. Corrected tax figures

These appeared in your JSON-LD, which Google reads and may surface directly.
Verified against primary sources on 18 Aug 2026:

| Claim | Was | Now | Source |
|---|---|---|---|
| Irish R&D tax credit | 25% | **35%** (Budget 2026; was 30% from 2024) | revenue.ie, citizensinformation.ie |
| Irish VAT thresholds | €80,000 / €40,000 | **€85,000 goods / €42,500 services** | revenue.ie |
| UK R&D | not stated | merged RDEC **20%**; ERIS 86% deduction + 14.5% payable credit, 30% intensity | gov.uk |
| `priceRange` | `"££"` | `"€€"` + `currenciesAccepted: EUR` | — |

### 6. New hero visual

The Unsplash stock photo is replaced with an animated SaaS revenue dashboard —
inline SVG and CSS, no image request, sharp on any display, and it reinforces
the SaaS positioning. Figures are labelled **Sample** in the UI so it can't be
read as real client data. All motion is disabled under
`prefers-reduced-motion`.

### 7. Two bugs fixed along the way

- **Chat auto-scroll on load.** The AI panel called `scrollIntoView` on mount,
  yanking every visitor past the hero into the middle of the page. It now only
  scrolls after you actually send a message.
- **Mobile hero order.** The visual was set to `order: -1`, pushing the H1 and
  the primary CTA below the fold on phones. Headline comes first now.

## After deploying

1. **Check `www` redirects to the apex.** Your canonical is
   `https://foundrbooks.com/` but you were inspecting the `www` URL in Search
   Console. In Vercel → Domains, make sure `www.foundrbooks.com` 308-redirects
   to `foundrbooks.com`.
2. **Use a Domain property in Search Console** so both variants report together.
3. **Resubmit the sitemap** — it now lists both indexable routes and is
   regenerated on every build. This should clear the "Temporary processing
   error".
4. **Request indexing** for `/saas-accounting`.
5. **Verify the fix**: URL Inspection → Test live URL → check the *rendered
   HTML* tab. You should now see real content, not the noscript message.

## Still worth your attention (not changed — your call)

- **Mixed geography.** Every meta tag targets UK & Ireland, but the hero trust
  row and footer say "Ireland & Spain" and the phone number is +34. Pick one
  story; the mixed signal hurts trust and local relevance.
- **`cashinify@gmail.com`.** A Gmail address on an ACA-qualified practice's site
  costs conversions. `hello@foundrbooks.com` is a five-minute fix in your DNS.
- **Testimonials.** You've confirmed these are real clients. Worth keeping
  written consent on file, and linking to a third-party review profile
  (Google Business Profile or Trustpilot) so they're independently verifiable.
- **One page is still thin.** `/saas-accounting` is a strong start, but ranking
  in this market needs more: R&D credits, VAT/OSS, and Ireland-vs-UK
  incorporation would each support their own page.
